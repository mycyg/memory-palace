# MemoryPalace 1.0

[中文](README.md) · [English](README.en.md) · **日本語**

MemoryPalace は、ツール連携、コンパニオン、知識の蓄積に使えるシングルユーザー向け記憶システムです。情報源、事実、経験、関係、約束、知識チャンク、継続状態を保存します。プラグイン、CLI、管理画面、HTTP、MCP、SDK から利用できます。

![MemoryPalace 構成図](docs/diagrams/overview.png)

## 機能

- **データの取り込み**：元の情報源を保存し、重複を除いて処理の進捗を記録します。モデルのリクエストが失敗しても、保存済みの情報源と進捗は残ります。
- **記憶の種類**：エピソード、事実や状態、手順、関係、共有体験、約束やリマインダー、日記、自己記述、知識、checkpoint を記録します。プロジェクト、役割、コレクション、現実・創作世界ごとに適用範囲を指定できます。
- **検索**：正確な手がかり、全文、意味、画像、関係から記憶を探せます。過去の時点の記録も読み取れます。結果には訂正後の状態を反映し、コンテキスト予算に収まる内容を選んで、ホスト間の重複を取り除きます。
- **バックグラウンドでの整理**：情報源から記憶を抽出し、競合への対処を提案して、トピックファミリーや叙事ボリュームを整理します。要約、日記、プロフィールには出典を残します。整理結果の改訂とロールバックも可能です。
- **ファイルとメディア**：PDF、DOCX、PPTX、XLSX、Markdown、HTML、CSV、画像、音声、動画を取り込みます。元のページ、段落、表、時刻、添付ファイルへの参照を保持します。
- **自発的な連絡**：役割ごとに通知、約束の確認、記念日、状況確認、挨拶を設定できます。タイムゾーン、通知を控える時間帯、頻度、送信前の確認方法を指定し、送信待ちの内容を延期・取消できます。送信待ちの内容と配信履歴は、再起動後も残ります。
- **管理画面**：処理状況を確認し、記録を閲覧して、出典や改訂内容を調べられます。タイムライン、カレンダー、2D／3D 関係図、知識と添付ファイル、日記、検索実験、連絡の設定、データ管理にも対応します。

モデルが生成した内容には、そのことを明記します。推論、ユーザーの明示的な発言、観測された操作は区別して記録します。同じ出典を繰り返し引用しても、独立した証拠の数は増えません。

### 書き込みと訂正

記憶には、出典をたどれて、後から訂正できることが必要です。ユーザーの明示的な発言とモデルの推論は別々に記録し、プロジェクト、役割、時期による違いは、それぞれの範囲で有効な記録を上書きせずに保持できます。訂正は現在の読み取りに反映し、改訂履歴も残します。モデルの処理が失敗しても情報源と完了済みの進捗を保持し、未完了の処理を再開できます。

![書き込みと訂正](docs/diagrams/write-correct.png)

### 検索とコンテキスト

検索では、その記憶が現在の問いに適しているか、会話のコンテキストにどれだけの内容を収められるかを優先します。プロジェクト、役割、時間の範囲で候補を絞り、有効な状態かを確認して、無関係な内容や失効した内容の混入を減らします。日常のやり取りでは高速な検索を使い、関係や履歴を詳しく調べる必要があるときに検索を深められます。結果には出典と読み取り先を残し、イベント全体や文書の章を続けて参照できます。

![検索とコンテキスト](docs/diagrams/recall-context.png)

### バックグラウンドでの整理

記録の変化に応じて長期的な整理をバックグラウンドで進め、現在のやり取りへの影響を抑えます。トピック、日記、要約には引用した情報源を残します。分類や生成された叙述によって記録の確かさが増したり、モデルの推論がユーザーの事実に変わったりすることはありません。情報源が訂正されると、影響を受ける派生内容は未確認としてマークされ、その後の読み取りでも有効な状態かを確認します。

![バックグラウンドでの整理](docs/diagrams/background.png)

### 自発的な連絡

連絡のタイミング、頻度、内容の範囲はユーザーが役割ごとに設定し、通知を控える時間帯や送信前の確認方法も送信条件に含めます。送信前には対象の事項が完了、取消、失効していないかを再確認し、古い状態に基づく連絡を避けます。ポリシーやチャネルを設定していない間は、プレビューできる提案だけを生成します。チャネルで配信を確認できない場合は、不確実な状態を残し、ユーザーが確認できるようにします。

![自発的な連絡](docs/diagrams/proactive-contact.png)

## インストール

Python 3.11–3.13、Node.js 22、[uv](https://docs.astral.sh/uv/) が必要です。

```sh
git clone https://github.com/mycyg/memory-palace.git
cd memory-palace
uv sync --frozen --extra all --extra dev
npm ci --prefix sdk/typescript
npm run build --prefix sdk/typescript
npm ci --prefix console
npm run build --prefix console
uv run eventmem console
```

管理画面とサービスの既定のアドレスは `http://127.0.0.1:8319` で、個人データは `~/.memorypalace` に保存されます。`eventmem serve` でサービスを起動し、`--root /private/path` で独立したデータディレクトリを指定できます。

管理画面で抽出、競合の判定、要約、再ランキング、embedding、視覚、ASR などの役割にモデルを割り当てます。互換 API やローカルのエンドポイントを利用でき、複数の役割で同じモデルを使うこともできます。認証情報は環境変数名で参照します。モデルを設定していない役割のタスクは設定待ちと表示され、元の情報源は保存されます。

## 接続と使用例

| 接続 | 機能 |
|---|---|
| Claude Code プラグイン | メッセージとツールの記録を収集。起動時の復元、操作前の検索、圧縮後の復元、終了処理に対応 |
| Codex ネイティブ hooks + MCP | 入力・最終応答・ツール結果を記録し、起動時と入力前に記憶を検索。圧縮後の復元と ACP／WeChat ホストに対応 |
| `dsh-eventmem` | DeepSeek Harness のイベントを共通サービスへ送信。旧版モードを明示的に有効にして切り戻し可能 |
| HTTP `/v1` | 情報源、記憶、訂正、関係、継続状態、ジョブ、管理、配信、観測 |
| MCP | stdio・Streamable HTTP によるツールアクセス |
| Python／TypeScript SDK | 記憶サービスの呼び出しとコールバックの重複排除に対応 |
| `eventmem` CLI | サービス、管理画面、MCP、取り込み・検索、移行、バックアップ、配信、評価 |

MCP はツールとしてのアクセスを提供します。自動収集やコンテキストの受動的な注入には、ホストのイベントアダプターが必要です。プラグインを使う間はローカルサービスを起動しておいてください。

`uv run eventmem codex install --project /path/to/project` で Codex のネイティブフックを導入できます。再起動後、`/hooks` で MemoryPalace の定義を確認して信頼してください。[Codex 接続ガイド](docs/codex.md)に MCP、共有コンパニオン記憶、WeChat ACP の設定を掲載しています。

```sh
uv run python examples/v1/scenarios.py tool
uv run python examples/v1/scenarios.py companion
uv run python examples/v1/scenarios.py knowledge
node examples/v1/tool.mjs
```

[実行可能な例](examples/v1/)には、ツール作業、共有体験と約束、文書の取り込み、連絡用コールバックがあります。送信ポリシーとチャネルが設定されるまでは、送信候補の提案だけを生成します。コールバックには固定の delivery id を使って重複を排除します。チャネルが冪等性に対応していない場合は、配信状態が不確実であることを表示します。

## 実測性能

テスト環境は **10 コア CPU、64 GiB RAM、SSD、macOS arm64、Python 3.13.14** です。データには 10 万件の記憶と、人工的に生成した 100 万件の 1,024 次元知識ベクトルを使用し、クエリには独立したサンプルを使いました。

| 指標 | 実測 |
|---|---:|
| ローカル高速検索 p95／p99 | 20.01／20.74 ms |
| 100 万ベクトル検索 p95／p99 | 39.12／41.29 ms |
| ANN Recall@20 | 0.9985 |
| 検索込みコンテキスト構成 p95 | 18.76 ms |
| バックグラウンド取り込み中の検索 p95 | 30.32 ms |
| 構築を含むピーク RSS | 2.75 GiB |
| 並行重複排除 | 10 セッション、400 要求、200 件の一意な情報源 |

表の遅延には外部モデルへのリクエストを含みません。実データでの品質は別途検証する必要があります。[テストの詳細](docs/performance.md)。

## 移行と保存

```sh
uv run eventmem migrate /old/project/.memory --root /isolated/memorypalace
uv run eventmem backup /private/backup.tar.gz --root /isolated/memorypalace
uv run eventmem restore /private/backup.tar.gz --root /another/empty/root
```

移行時は元の id、内容、アーカイブ、改訂の関連付け、出典への参照を保持し、独立した移行先でデータを検査します。旧データベースは上書きしません。見つからない外部情報源は明示します。アーカイブでは履歴を保持し、永久削除では情報源と、それに依存する派生データを処理します。エクスポート済みのファイルとバックアップは別途管理してください。

## ドキュメントと制限

[アーキテクチャと意味論](docs/architecture.md) · [設定・プラグイン・運用](docs/operations.md)

高速全文検索では、指定範囲で一致した記録のうち、直近の最大 400 件を順位付けします。深度検索では一致した記録全体を対象にでき、必要に応じてモデル検索も使えます。

PDF は既定で文書内のテキストを直接解析します。スキャンしたページには視覚エンドポイントが必要です。ローカルで動作する完全なレイアウトモデルはオプションです。視覚検索には、互換性のあるマルチモーダル embedding エンドポイントが必要です。外部モデル、負荷の高い解析、データ分布の違いによって、処理全体の遅延と品質は変わります。

macOS／Linux 上でのシングルユーザー向けローカル運用に対応します。
