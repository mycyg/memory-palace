# MemoryPalace 1.0

[中文](README.md) · [English](README.en.md) · **日本語**

MemoryPalace は、ツール連携、コンパニオン、知識の蓄積に使えるシングルユーザー向け記憶システムです。一つの Python コアで情報源、事実、経験、関係、約束、知識チャンク、継続状態を管理します。プラグイン、CLI、管理画面、HTTP、MCP、SDK から利用できます。

![MemoryPalace 構成図](docs/diagrams/overview.png)

## 機能

- **データの取り込み**：情報源のスナップショットとハッシュを保存し、重複排除、トランザクション、revision の検査を通じてデータを書き込みます。処理の進捗は永続ジョブで管理します。モデルのリクエストが失敗しても、保存済みの情報源と進捗は残ります。
- **記憶の種類**：エピソード、事実や状態、手順、関係、共有体験、約束やリマインダー、日記、自己記述、知識、checkpoint を記録します。プロジェクト、役割、コレクション、現実・創作世界ごとに適用範囲を指定できます。
- **検索**：正確な手がかり、FTS5、LanceDB ベクトル、視覚ベクトル、関係から検索した候補を統合します。過去の時点の記録を読み取ることもできます。結果を返す前に有効な状態かを再確認し、コンテキスト予算に収まる内容を選び、ホスト間の重複を取り除きます。
- **バックグラウンドでの整理**：抽出や競合処理の案を生成し、増分 Leiden 分類を実行して、トピックファミリーや叙事ボリュームを管理します。要約、日記、プロフィールには出典を残します。整理結果の改訂とロールバックも可能です。
- **ファイルとメディア**：PDF、DOCX、PPTX、XLSX、Markdown、HTML、CSV、画像、音声、動画を取り込みます。元のページ、段落、表、時刻、添付ファイルへの参照を保持します。
- **自発的な連絡**：役割ごとに通知、約束の確認、記念日、状況確認、挨拶を設定できます。タイムゾーン、通知を控える時間帯、頻度、送信前の確認方法を指定し、送信待ちの内容を延期・取消できます。配信履歴は保存されます。
- **管理画面**：処理状況を確認し、仮想スクロールで記録を閲覧して、出典や改訂内容を調べられます。タイムライン、カレンダー、2D／3D 関係図、知識と添付ファイル、日記、検索実験、連絡の設定、データ管理にも対応します。

モデルが生成した内容には、そのことを明記します。推論、ユーザーの明示的な発言、観測された操作は区別して記録します。同じ出典を繰り返し引用しても、独立した証拠の数は増えません。

## インストール

GitHub リポジトリからインストールします。このリリースでは PyPI・npm への自動公開は行いません。Python 3.11–3.13、Node.js 22、[uv](https://docs.astral.sh/uv/) が必要です。

```sh
git clone https://github.com/mycyg/memory-palace.git
cd memory-palace
uv sync --frozen --extra all --extra dev
npm ci --prefix sdk/typescript
npm run build --prefix sdk/typescript
npm ci --prefix console
npm run build --prefix console
uv run eventmem console
```

管理画面とサービスの既定のアドレスは `http://127.0.0.1:8319` で、個人データは `~/.memorypalace` に保存されます。`eventmem serve` でサービスを起動し、`--root /private/path` で独立したデータディレクトリを指定できます。サービスはローカルの認証情報、Host、Origin を検査します。実際の記憶、添付ファイル、認証情報、実行ログはリポジトリに含めません。

管理画面で抽出、競合の判定、要約、再ランキング、embedding、視覚、ASR などの役割にモデルを割り当てます。互換 API やローカルのエンドポイントを利用でき、複数の役割で同じモデルを使うこともできます。認証情報は環境変数名で参照します。モデルを設定していない役割のタスクは設定待ちと表示され、元の情報源は保存されます。

## 接続と使用例

| 接続 | 機能 |
|---|---|
| Claude Code プラグイン | メッセージとツールの記録を収集。起動時の復元、操作前の検索、圧縮後の復元、終了処理に対応 |
| `dsh-eventmem` | DeepSeek Harness のイベントを共通サービスへ送信。旧版モードを明示的に有効にして切り戻し可能 |
| HTTP `/v1` | 情報源、記憶、訂正、関係、継続状態、ジョブ、管理、配信、観測 |
| MCP | stdio・Streamable HTTP によるツールアクセス |
| Python／TypeScript SDK | OpenAPI から生成した共通の契約を使用し、コールバックの重複排除インターフェースを提供 |
| `eventmem` CLI | サービス、管理画面、MCP、取り込み・検索、移行、バックアップ、配信、評価 |

MCP はツールとしてのアクセスを提供します。自動収集やコンテキストの受動的な注入には、ホストのイベントアダプターが必要です。プラグインを使う間はローカルサービスを起動しておいてください。

```sh
uv run python examples/v1/scenarios.py tool
uv run python examples/v1/scenarios.py companion
uv run python examples/v1/scenarios.py knowledge
node examples/v1/tool.mjs
```

[実行可能な例](examples/v1/)には、ツール作業、共有体験と約束、文書の取り込み、連絡用コールバックがあります。送信ポリシーとチャネルが設定されるまでは、送信候補の提案だけを生成します。コールバックには固定の delivery id を使って重複を排除します。チャネルが冪等性に対応していない場合は、配信状態が不確実であることを表示します。

## 実測性能

検証には **10 コア CPU、64 GiB RAM、SSD、macOS arm64、Python 3.13.14** の環境を使用しました。データは 10 万件の記憶、100 万件の 1,024 次元知識ベクトルと、それに対応する SQLite レコードです。ベクトルは固定シードの 256 成分ガウス混合分布から生成し、クエリには独立したサンプルを使いました。

| 指標 | 実測 |
|---|---:|
| ローカル高速検索 p95／p99 | 20.01／20.74 ms |
| 100 万ベクトル検索 p95／p99 | 39.12／41.29 ms |
| ANN Recall@20 | 0.9985 |
| 検索込みコンテキスト構成 p95 | 18.76 ms |
| バックグラウンド取り込み中の検索 p95 | 30.32 ms |
| 構築を含むピーク RSS | 2.75 GiB |
| 並行重複排除 | 10 セッション、400 要求、200 件の一意な情報源 |

表の遅延には外部モデルへのリクエストを含みません。実データでの品質は別途検証する必要があります。[条件・生データ・再現方法](docs/performance.md)では、初回の検索、一般語の検索、取り込み中の検索、モデルへのリクエスト、リプレイの結果をそれぞれ報告しています。SCARLETT との機能比較は提供された構成図だけに基づきます。実測による性能比較はなく、優位性を主張するものではありません。

## 移行と保存

```sh
uv run eventmem migrate /old/project/.memory --root /isolated/memorypalace
uv run eventmem backup /private/backup.tar.gz --root /isolated/memorypalace
uv run eventmem restore /private/backup.tar.gz --root /another/empty/root
```

移行時は元の id、内容、アーカイブ、改訂の関連付け、出典への参照を保持し、独立した移行先でデータを検査します。旧データベースは上書きしません。見つからない外部情報源は明示します。アーカイブでは履歴を保持し、永久削除では情報源と、それに依存する派生データを処理します。エクスポート済みのファイルとバックアップは別途管理してください。

高速全文検索では、指定範囲で一致した記録のうち、直近の最大 400 件を順位付けします。深度検索では一致した記録全体を対象にでき、必要に応じてモデル検索も使えます。

PDF は既定で文書内のテキストを直接解析します。スキャンしたページには視覚エンドポイントが必要です。ローカルで動作する完全なレイアウトモデルはオプションです。視覚検索には、互換性のあるマルチモーダル embedding エンドポイントが必要です。外部モデル、負荷の高い解析、データ分布の違いによって、処理全体の遅延と品質は変わります。

macOS／Linux 上でのシングルユーザー向けローカル運用に対応します。このリリースには、複数ユーザーのアカウント管理、カメラ・マイクのリアルタイム収集、専用チャットクライアントは含みません。
